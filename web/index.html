                      What a match proves, and what it does not

                      Built

                      A match means the bytes your browser received are exactly the bytes the manifest lists. It does not show that anyone approved them: no report has been approved or published from this preview build yet.

                      Comparing with an approved hash is unavailable because nothing has been approved or published from this preview build yet.

                      How verification grows

                      Partly planned
                      1. Fetch the manifest (built)The page downloads the manifest and every file it lists.
                      2. Recompute each hash here (built)Your browser hashes each file with SHA-256. No server is trusted for this step.
                      3. Compare with the approval (planned)Each published file will show a match or a mismatch against the hash the media officer approved.
                      4. Follow corrections (planned)A corrected report will show its own approval and link back to the version it replaces.

                      About

                      What Agon is for

                      Agon is planned as the full-time newsroom for a small club media office. Everything below describes the build in progress. Nothing on this page is deployed as a working service yet.

                      Who it is for

                      The media and supporter office of a professional football club. In the hour after the whistle, a very small team has to publish the match report, bulletins for supporters abroad, accessible versions and an item for the club website.

                      What is real in this preview

                      Built

                      This preview is a static site. The Match Centre replays synthetic matches from the generator's event files, with fictional names from each seed's names file, and the Verify page recomputes those files' hashes in your browser. The Newsroom Wall, the stand-in approval card and the recap show one run, labelled on every screen as a design preview: sample run written by hand, not produced by the pipeline. Its gate verdicts and its bundle hash are computed by the real checks and the real seal over those hand-written sentences. No agents run, nothing is published and no account is needed.

                      What will happen at full time

                      Planned
                      1. Read the matchAgents read the fictional match's event log through a read-only data tool.
                      2. Write and translateMicrosoft Foundry agents write the club's report, translate it into Greek, Spanish and French, and add an easy-read edition and audio.
                      3. Check in codePlain code checks every number, name and minute against the log in every language, and blocks real club or player names.
                      4. Wait for a personA Microsoft Agent Framework workflow seals the bundle under a content hash and waits until the media officer approves that exact hash on a card in Microsoft Teams.
                      5. Publish only what was approvedThe approved files go to the club's feed and public recap page, and nothing else does.

                      Where approval happens

                      Planned

                      The media officer approves in Microsoft Teams, where the office already works. If the Teams route is unavailable, a signed single-use link carries the same decision to the same check. On this public site, a clearly labelled stand-in card will call that same check.

                      Data and names

                      Every club, player and match is synthetic and fictional. Agon is not affiliated with or endorsed by any league, club or broadcaster, and it shows no real crests or logos.
